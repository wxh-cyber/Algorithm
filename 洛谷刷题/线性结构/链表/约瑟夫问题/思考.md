# 思考

<hr />

## 如何理解采用STL写法时的`erase`函数？最终返回了什么？

`it = l.erase(it) `这一行，erase 做了两件事：

1. 把 `it` 指向的结点**从链上摘除并销毁**（析构元素、释放结点内存）；
2. 返回一个指向**被删元素的后继**（紧跟在它后面那个元素）的有效迭代器；**若删的是最后一个元素，则返回 `end()`**。

所以返回值不是“删除位置”，不是“前驱”，而是 “**接班人”的位置**。

<br />

## 为什么设计成返回后继？

动机只有一个：**支持“边遍历边删”的循环惯用法**。删除发生后，指向原结点的迭代器必然悬空，而遍历者唯一需要知道的新位置就是后继——返回它，你才能无缝继续。返回任何别的值（旧位置已释放、前驱意味着倒退）都没有意义。

<br />

## 底层机制

`std::list` 是带头哨兵结点的双向循环链表，`erase(pos)` 内部大致等价于：
```cpp
Node* p   = pos.node;
Node* nxt = p->next;          // ① 先记住后继
p->prev->next = nxt;          // ② 前驱跳过 p
nxt->prev = p->prev;          // ③ 后继回指前驱
destroy(p->val); delete p;    // ④ 销毁结点
return iterator(nxt);         // ⑤ 返回后继
```

<br />

## 迭代器失效规则：`list`的独特优势

| 容器 | `erase(pos)`后失效范围 |
| :-- | :-- |
| `vector`/`deque` | `pos`及其**之后所有**迭代器失效（元素搬移） |
| `list` | **仅指向被删结点的迭代器失效**，其余全部依然有效 |
